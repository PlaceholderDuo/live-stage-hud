HANDOFF 3: Song Metadata Repair (BPM + Key + Naming)
═══════════════════════════════════════════════════════════════
Context: 258 songs have @time=N but ~240 of them are wrong
because @time was computed from @bar using BPM=120 (default
placeholder). The HUD will show lyrics at wrong times until
the BPM field in meta.json is corrected to the actual tempo.

This handoff fixes BPMs, standardizes keys, and cleans up
song names. All work touches ONLY meta.json files in
~/ReaperSongs/. Zero overlap with any other handoff.

═══════════════════════════════════════════════════════════════
THE PROBLEM
═══════════════════════════════════════════════════════════════

The verify script reports BPM=120 for ~300 of 324 songs.
That's the default — not the real tempo. When we migrated
@bar→@time, we used this wrong BPM:

  time = (bar - 1) * 4 * 60 / 120   ← wrong if song is 94 BPM

At 94 BPM vs 120 BPM, a song drifts 28% by the end:
  - Verse 1 starts at bar 19 → @time=36.0s (should be 46.1s)
  - Chorus at bar 45 → @time=88.0s (should be 112.3s)
  - The HUD shows lyrics 10-24 seconds EARLY for a typical song

After we fix BPMs, we re-run migrate-to-atime.js (already built)
to recompute @time with correct values. The result: accurate
time-based lookup for 258 songs without needing LRCLIB at all.

═══════════════════════════════════════════════════════════════
TASK 1: Build BPM Lookup Script
═══════════════════════════════════════════════════════════════

Create tools/fix-metadata.js that reads every meta.json,
looks up the real BPM, and writes it back. Two strategies:

Strategy A — Spotify API (preferred, accurate):
  - Search: artist + title → get track → audio_features endpoint
  - Returns: tempo (BPM), key, mode, time_signature, energy, etc.
  - Rate limit: ~180 requests/min with app credentials
  - No user login needed — client credentials flow
  - Registration: developer.spotify.com → create app → get
    client_id + client_secret
  - Store credentials in data/spotify-credentials.json (gitignored)

Strategy B — Local audio analysis (fallback, no API needed):
  - Check ~/ReaperSongs/<Song>/ for .wav/.mp3/.flac files
  - Use lib bpm-detective or web-audio-api
  - Accurate if backing track audio exists in song folder
  - Requires: npm install bpm-detective

Implementation:
  - Try Spotify first (fast, accurate)
  - Fall back to local audio if no Spotify match
  - Fall back to manual flag: mark song as "needs BPM"

For each song, update meta.json:
  {
    "bpm": 94,              ← was 120, now real
    "key": "Am",            ← kept if already set, filled from Spotify
    "bpm_source": "spotify"  ← new field — tracks provenance
  }

═══════════════════════════════════════════════════════════════
TASK 2: Re-run @time Migration with Correct BPMs
═══════════════════════════════════════════════════════════════

After Task 1 fixes BPMs, the @time values in song.chopro are
still computed from the OLD BPM=120. Re-run the migration:

  node tools/migrate-to-atime.js

This reads the NOW-CORRECT bpm from meta.json and recomputes:
  time = (bar - 1) * 4 * 60 / correct_bpm

The script already exists and handles this. It only overwrites
lines that already have @time= prefix. Safe to re-run.

TASK 4: Deduplicate Song Variants
═══════════════════════════════════════════════════════════════

Many songs exist in duplicate:
  "Aint No Sunshine" vs "OFFICIAL AINT NO SUNSHINE TABS"
  "American Girl" vs "AMERICAN GIRL CHORDS (ver 2)"
  "Fins" vs "FINS CHORDS (ver 2)" vs "Fins Chords"
  etc.

Build tools/dedupe-songs.js that:

A) Groups songs by normalized title + artist:
  - Normalize: lowercase, strip OFFICIAL/TABS/CHORDS/verN
  - Group songs with matching normalized names

B) For each group with >1 song:
  - Score each variant:
    +1 per @time=N annotation
    +1 per chord bracket [A] [G] etc
    +1 if BPM != 120 (real BPM vs default)
    +1 if key is set (not empty)
    +1 if lyrics.length > 20 lines
  - Keep the highest-scoring variant
  - Move others to ~/ReaperSongs/_duplicates/ (archive, not delete)

C) After dedup, update meta.json of kept songs:
  - Take the best BPM, key, tuning, capo from any variant
  - Merge lyric sections if one variant has better section data
  - Add a "deduplicated_from" field listing merged sources

D) Run with --dry-run first to preview:
  node tools/dedupe-songs.js --dry-run
  node tools/dedupe-songs.js   (for real)

TASK 5: Key Completion
═══════════════════════════════════════════════════════════════

Many meta.json files have "key": "" (empty). Fill these in.

Sources (in priority order):
  1) Spotify API — already in our data from Task 1
  2) From song.chopro: parse {key: Am} directive
  3) From the key-fallback.json already in data/ (76 entries)

     most common root note — that's likely the key

Build into fix-metadata.js as a sub-task. Add "key_source"
field: "spotify" / "chopro" / "fallback" / "detected".
