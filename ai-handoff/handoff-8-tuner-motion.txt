THE PROVEN BEHAVIOR (port this verbatim logic)
═══════════════════════════════════════════════════════════════

A vertical band (2 columns wide) sweeps left↔right. Its SPEED is
proportional to |cents| (distance from in-tune). As the player
gets closer, the band DECELERATES. When |cents| < ~3 the band
goes essentially stationary and turns GREEN = locked.

  |cents|       band speed        color
  ─────────────────────────────────────
  > 20          max sweep         RED    (visibly way off)
  3 < |c| < 20  slowing           AMBER  (hunting it down)
  |c| < 3       ~0 (stops)        GREEN  (LOCKED)

Key design (do NOT skip):
- speed = smoothstep-decay, NOT teleport. Band position integrates
  velocity over time so it physically glides / slows / stops
  (this is what makes "less it moves, more you're in tune" true).
- The band bounces off the grid edges and keeps sweeping while
  out of tune. Only reaching in-tune stops it.
- Trigger-behaviour: ANY pad press exits the tuner.

Exact tuning constants proven in nova-script (source of truth):
  Speed per cent:       speed += cents * 0.18, capped at 7.0
  Smoothing:            speed lerp toward target each frame
  Lock threshold:       locked = |cents| < 3 AND speed < 0.4
  Near threshold:       NEAR_CENT = 20 (below this turn amber)
  Band width:           ~1.5 columns
  Bounce bounds:        band_x between 0.6 and 6.4 on an 8-wide grid

Port the *math*, not the layout — on iPhone you have real pixels,
so you can use a WIDER band and a smooth gradient bar instead of
chunky 2-pixel columns.

TASK 2: REAPER pitch/tuner integration (tried-and-tested path)
═══════════════════════════════════════════════════════════════
Use REAPER's BUILT-IN tuner, exposed over the existing OSC
control surface. Do NOT hand-roll an FFT on the iPhone.

REAPER's native OSC tuner mechanism: Reaper → Options →
Control/OSC/web → enable "Send Center Note for row". The tuner
browser players announce the center/default via a JSFX that
pushes pitch to a control surface. The robust, verified method:
  A JSFX pitch-tracking plugin pushes "detected_freq" → a small
  ReaScript / LUA reads it → sends OSC to our :8080 server.

Because this is the "unknown of the session", keep it decoupled:
  server.js already routes /nova/tuner/{} similarly to V25 values.

So restate TASK 2 as a PROBE FIRST:
  A) Research + pick ONE working REAPER→OSC tuner feed today:
     - builtin Reaper OSC tuner / control-surface feedback
     - OR a ReaPack "Tuner" JSFX that exposes a raw `freq`.
  B) The minute a raw `freq` appears, convert to cents:
       cents = 1200 * log2(freq / targetFreq)
       targetFreq from nearest chromatic note or a fixed tuning.
     Push to server as /nova/tuner { cents, channel }.
  Do this empirically and commit what actually worked.

Phone side should degrade gracefully: if no tuner feed for
>1500ms set state.tuner.cents = null → iPhone shows "NO SIG"
grey band instead of pretending.
