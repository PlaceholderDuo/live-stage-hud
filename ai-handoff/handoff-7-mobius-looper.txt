═══════════════════════════════════════════════════════════════
HANDOFF 7: Mobius Looper iPhone Page
═══════════════════════════════════════════════════════════════
The server has full Mobius looper MIDI control (CC 20-26 for
Record/Play/Overdub/Multiply/Mute/Reset/Undo) but the iPhone
controller has NO dedicated looper page. This handoff builds it.

Files: controller.js, controller.css, index.html
Zero overlap — new page, new buttons, server routing already exists.

═══════════════════════════════════════════════════════════════
WHAT EXISTS
═══════════════════════════════════════════════════════════════

Server already has (server.js):
  - Virtual MIDI output "Live Show Manager"
  - CC mapping: Record=20, Play=21, Overdub=22, Multiply=23,
    Mute=24, Reset=25, Undo=26
  - Action handlers: mobiusRecord, mobiusPlay, mobiusOverdub,
    mobiusMultiply, mobiusMute, mobiusReset, mobiusUndo
  - These send MIDI CC 20-26 on the virtual port
  - REAPER routes this to the Mobius VST track

iPhone controller has:
  - sendCommand() function already routes action → WebSocket → server
  - RegisterPage() pattern for modular pages
  - No existing Mobius page or buttons

FUTURE: Mobius Feedback Loop
═══════════════════════════════════════════════════════════════

Currently the loop state indicators will show placeholders because
Mobius doesn't send state feedback to the REAPER Lua runner.
The runner's _collectLoopStates() returns empty.

When this is implemented (handoff 4 or later), the indicators
will light up automatically — the page structure supports it
from day one. Just need state.loopStates = [{track:1, state:"playing"},...]
in the WebSocket broadcast.
